# 鸟类头眼清晰度

第九版鸟类评分由原图眼部结构、关键点定位和头眼局部测量共同决定。整只鸟中清楚的羽毛或翅膀不参与正式分数；旧鸟体估计保存在 `body_sharpness` 中，供诊断使用。此功能不修改照片总分、分类、星级或收藏。

## 选片参考分

2026-11-06 起，按用户最终选择，详情、列表标记和悬浮信息主要展示 **0–10 的头眼清晰度参考分**，界面直接展示分数，不附加量程标注。只有头眼位置与测量均得到当前版本核验、且符合完整入镜与大小要求的鸟才有有效分数；无法确认时分数留空，标记“待复核”。不能把未知填成 0 或 5，也不把合格、不合格机械映射成 10、0。

分数为全部参与眼周及头部测量的最低值，保留两位小数，界面显示一位小数。例如原测量 2.0 显示为 2.0，8.62 显示为 8.6。分数不是识别置信度或清晰百分比；精度仍受原图细节和既有边缘宽度模板限制，调整分制不会提升定位精度或产生新的测量细节。翅膀、背景或另一只眼的高分不能补偿已参与眼周的模糊。

每只鸟分别保留 `focus_score`。照片采用达到大小门槛且完整入镜的有效候选中最高的参考分，`focus_score_index` 指明对应鸟；身体不完整或完整性不确定的候选不产生有效分，不通过填零混入清晰度排序。较小候选仍可查看，但不决定照片参考分。完整入镜检查基于检测范围及原图边界，不能证明没有遮挡或重叠鸟体融合。

结论由 `models/bird_assessment.py` 从原始证据派生，规则版本为 `bird-selection-v3-score10`。原数据库 0–10 参考值保留，数值排序和旧链接继续使用该内部尺度；头眼清晰度与筛选器范围文字统一使用 0–10，保持旧筛选条件兼容。列表和详情读取时共用核验规则，并检查原图签名；原图变化、规则过旧或缺少有效证据时，新分数为空。没有迁移或覆盖既有照片数值。

三态保留在内部诊断信息中，不作为主要显示，也不决定连续参考分能否处于中间范围。例如有效测得 6.4 时可以显示 6.4；不能因为其落在内部复核区间就强行变成 5。内部模糊区不高于 3.0、清楚区不低于 7.5，均是未经独立人工样本集校准的工程区间，不能视为普遍合格线或准确率保证。没有完整有效测量时，即使能看出某一头部区域模糊，也不编造一个精确的头眼综合分。

本机三张已知样片的核查目标：DSC02049.JPG 为 2.0，DSC00935.JPG 为 2.0，DSC02086.JPG 为 8.62（显示为 8.6），后者对应右下方的完整海鸥。识别不稳定的案例仍保留待复核，分数展示本身不等于头眼误识别已解决。

## 定位模型

使用 [SuperPicky 发布的鸟类关键点权重](https://huggingface.co/jamesphotography/SuperPicky-models/tree/939fbccdb0a9af538b218a77e19db3e01c05f399)：`cub200_keypoint_resnet50.onnx`，约 99 MB（兆字节）。模型采用 ResNet50（50 层残差网络），输出左右眼、喙的归一化坐标与可见性概率；这些概率不作为清晰度分数。发布者标注权重许可为 GPL-3.0（第三版通用公共许可证），详情见发布页。仓库不打包模型权重；定位适配和清晰度测量由本项目实现，未复制发布者的评分代码。

下载固定在 `939fbccdb0a9af538b218a77e19db3e01c05f399`，安装时验证 SHA-256（256 位安全散列算法）：`2b62d30e36357b807a909fb22ae55323f768feb2957fbf4ecbd840bd7525f514`。文件存入项目的 `pretrained_models/birds/`，不提交到代码库。通过 ONNX Runtime（开放神经网络交换格式的推理运行库）在本机处理器上运行，不上传照片，不执行外部模型代码。该运行库沿用项目安装脚本为人脸识别配置的依赖。

输入为鸟体定位框的彩色原图裁剪，缩放至 416 × 416；按模型的三个通道均值 `[0.485, 0.456, 0.406]` 和标准差 `[0.229, 0.224, 0.225]` 归一化。分别处理原裁剪和水平翻转裁剪，翻转后的左右眼需交换并映射回原坐标。

原图和翻转图不能形成有效定位时，增加一次鸟体外背景抑制：仅在定位模型的输入中，将分割范围外的像素设为中性灰色，再运行原方向和水平翻转两个观察。每个获准的位置都必须同时有至少一个未改动背景的原图观察，以及一个背景抑制后的观察支持，并通过相同的可见性、位置和距离检查。最多增加两次模型推理；原来已经通过检查的目标不额外处理。

此补充步骤用于降低背景和重叠目标对定位的干扰，并不保证能分开所有重叠鸟。如果多对观察支持相互矛盾的头部，仍标记待复核。背景抑制后的图像只用于定位，不参与清晰度测量；`localization_attempts` 和 `support_views` 记录尝试及最终支持来源。

## 测量规则

1. 沿用候选大小门槛及画面边缘排除规则。仅对符合大小条件的完整候选测量头眼。
2. 眼睛及喙在支持该位置的两次观察中，可见性概率均至少为 0.65。两次定位的眼睛及喙偏移不得超过该眼眼喙距离的一半；使用两次坐标的平均位置。眼睛必须在鸟体分割内。补充定位保持这些门槛，不单凭背景抑制后的结果确认。
3. 眼喙距离至少为 54 个原图像素，且不得超过鸟框短边的一半。不满足时不能用整个鸟框猜测头部位置。
4. 关键点一致还不足以确认眼睛，必须经过下述眼部结构核验。核验通过后，以眼部候选的实际中心替代原关键点；区域半径沿用通过基础检查的眼喙尺度，分别为该距离的 0.45 倍和 1.2 倍，测量眼周与头部。圆形范围与鸟体分割相交，并排除约两格分割像素的轮廓误差和边缘剖面所需的安全距离。所有评分像素取自原图，不涂黑背景，也不把圆形边界当作图像边缘。
5. 头部测量区域最长边至多 768 像素，不放大小目标；同一只眼的头部与眼周使用同一缩放比例。测量可靠亮暗过渡的宽度，采用中位数而非最清楚的四分之一。分数为 `10 / (1 + (sigma / 2)²)`，其中 `sigma` 为估计的边缘过渡宽度。
6. 正式分数为眼周与头部测量中的最低分；两眼均通过定位条件时，两眼都参与这一上限。任何参与区域缺乏可靠细节时，不给出正式分数。

这些参数是尚待更多人工样本校准的工程门槛，不代表准确率或选片合格线。模型可能定位错误，眼周测量也不能等同于对眼球内部或睫毛逐像素判断。局部预览用紫色圆显示眼周、蓝色圆显示头部，便于人工复核。

## 眼部结构核验

模型可能在原图、翻转图和背景抑制图中共同把翼根当作眼睛。因此，第九版还检查原图中的局部结构：

- 以原关键点为中心，在眼喙距离 3.5 倍的有界邻域中查找暗色、紧凑的结构，候选中心必须在鸟体分割内。观察图最长边至多 1024 像素，单眼最多验证 8 个候选，按与原落点的距离排列，不按清晰度排列。
- 候选提取抑制小型眼内高光对暗色轮廓的干扰，但亮度对比仍取未经该处理的灰度图。候选内部必须比周围暗至少 12 个灰度级；圆度、凸度及惯性条件用于排除条纹和细长羽毛。
- 对每个候选裁剪局部上下文，再用同一关键点模型检查原方向与水平翻转。局部模型明确把眼睛定位到候选以外时，排除该暗斑，即使整鸟定位的置信度很高。
- 贴近原落点的结构，最多允许一个候选直径的偏移，可与原先已经通过检查的整鸟定位相互印证；局部裁剪缺少完整鸟体、置信度低时，不单凭这一低置信度否定原定位。远离原落点的修正则必须由局部两次观察明确支持：眼睛与喙的最低可见性概率均至少 0.65，两次眼睛位置都在候选一个直径以内，彼此偏移不超过半个直径，喙的位置及眼喙关系也需通过检查。
- 如果同一眼睛仍有相互分离的多个获准候选，保留待复核，不挑其中较清楚的一处评分。找不到获准结构时使用 `eye_unverified`，与已确认眼部但无法测量细节的 `eye_detail_insufficient` 区分。

暗色紧凑结构只是候选条件，不是眼睛的语义证明。这些局部条件与原模型交叉核验仍可能失败；黑色脸部、遮挡、极小眼睛或特殊姿态可能无法确认，此时不发布头眼分数。`eyes[].verification` 保存候选、局部核验依据及最终中心，原关键点继续保留，便于发现误定位。用于候选提取的处理图不参与清晰度评分。

## 无法判断与缓存

可靠测出模糊时保留低分。无法定位、定位不稳定、头眼太小或有效细节不足时，使用“待复核”，照片分数为空；不填零分，也不回退到鸟体分数。模型无法下载或加载时停止任务，不逐张覆盖成照片处理失败。

`SCORE_VERSION` 为 `bird-head-eye-edge-width-v9`，`FOCUS_CHECK_VERSION` 为 `head-eye-v3`。旧结果不进入当前版本的清晰度排序或筛选。再次检测会复用原图签名及检测模式相同的旧鸟体定位，重新读取原图核验并测量头眼；第七、八版的头眼定位结果也需要眼部结构核验。

改变大小门槛复用当前版本已测量的头眼；降低门槛时补测此前被排除的候选。尚未测量头眼的小鸟只保留鸟体诊断值，不向界面发布头眼分数。测量记录及坐标写入 `focus_evidence`，支持回看。
